# conversation-feedback Specification

## Purpose
为 `/litellm-audit-export` 审计导出提供一条独立于 OpenTUI 插槽、对 TUI 之外无法看到卡片反馈的 OpenCode 客户端（Desktop / Web）可用的会话内反馈通道：由用户显式开启开关后，导出结果以插件写定的确定性对话消息形式出现在当前会话，路径与状态不依赖模型生成。

## Requirements

### Requirement: 对话反馈开关
插件 SHALL 提供 `conversationFeedback` 布尔配置开关，默认关闭；非法取值 SHALL 按默认关闭处理并不得导致插件加载失败。开关关闭时，导出命令的反馈 SHALL 与未引入本能力时完全一致：TUI 卡片与 RPC 通道行为不变，不提交任何对话消息，不触发任何模型调用，且对会话输入 API 的调用量 SHALL 为零。开关开启时，导出**命令**每次执行 SHALL 按下述"导出结果对话反馈"要求提交反馈消息；程序化导出 RPC `export` MUST NOT 触发对话反馈或任何模型调用。文档 SHALL 说明开启后的成本（每次命令导出产生一轮模型调用）与隐私含义（反馈消息含报告路径，进入会话记录并可经宿主同步、会话导出或远端模型日志离开本机）。

#### Scenario: 开关默认关闭
- **WHEN** 用户未配置 `conversationFeedback` 或取值非法
- **THEN** 导出后不提交任何对话消息、不调用会话输入 API，TUI 卡片与 RPC `latest` 行为与既有能力一致，插件正常加载

#### Scenario: 非法取值容错
- **WHEN** `conversationFeedback` 被配置为非布尔值（如字符串 "yes"）
- **THEN** 插件按默认关闭处理并保持可用，不抛出加载错误

#### Scenario: RPC 导出不触发反馈
- **WHEN** 开关开启，但导出经 RPC `export` 程序化调用而非用户执行命令
- **THEN** 不提交任何对话消息、不触发模型调用，RPC 行为与结果与开关关闭时一致

### Requirement: 导出结果对话反馈
开关开启且导出命令执行完成时，插件 SHALL 通过会话输入通道向当前会话提交一条 user 消息，其文本由插件确定性地构造并 SHALL 以固定标识标注为插件生成，不冒充用户手写内容。成功消息 SHALL 包含：导出成功状态、报告完整绝对路径、发现状态与模型数，且该发现状态与模型数 SHALL 来自与写入报告文件相同的同一次快照捕获，MUST NOT 在文件写入完成后从可变发现状态二次读取。失败消息 SHALL 包含失败状态与经固定类别映射的简短原因，MUST NOT 包含任何路径（包括占位符或空路径）与原始异常文本。插件 SHALL 对路径做编码安全处理（至少转义换行与控制字符），MUST NOT 将路径拼接为可被解释为指令的文本。反馈消息本身 MUST NOT 包含报告 JSON 内容、逐模型清单、价格，且插件 MUST NOT 从连接凭据、配置、报告内容或原始上游响应中复制凭据；插件 MUST NOT 主动读取报告文件并送入模型，但 MUST NOT 承诺约束模型在后续 agent 回合中的工具使用行为，该风险 SHALL 在文档中披露。反馈提交失败或模型生成失败 MUST NOT 破坏报告文件、影响命令执行结果、既有卡片/RPC 通道或已提交的反馈消息本身。TUI 卡片通道的行为 MUST NOT 因本通道的存在而改变。

#### Scenario: 开关开启后成功导出
- **WHEN** `conversationFeedback` 开启，用户在 TUI 或 Desktop 执行 `/litellm-audit-export` 且报告写入成功
- **THEN** 当前会话出现一条含插件生成标识、状态、完整绝对路径、发现状态与模型数的对话消息，随后宿主按常规流程尝试模型回复；该消息文本由插件构造，不依赖模型生成

#### Scenario: 反馈与报告快照一致
- **WHEN** 反馈消息与报告文件在同一次导出中产生，且写入期间发现状态发生变化（如连接切换）
- **THEN** 消息中的发现状态与模型数仍对应写入报告文件的那次快照捕获，不与写入后重新读取的状态混搭

#### Scenario: 连接状态边界
- **WHEN** 导出命令执行时处于连接切换待发现、认证失败已清空、临时故障保留旧结果（stale）或成功发现空清单状态
- **THEN** 成功消息分别如实时标记这些状态与对应模型数（切换/清空为 0、stale 注明为保留的旧结果、空清单为 0），不沿用与当前状态不符的数量

#### Scenario: 开关开启后导出失败
- **WHEN** `conversationFeedback` 开启，导出执行失败（如目标目录不可写）
- **THEN** 当前会话出现一条含失败状态与映射后原因的对话消息，不含任何路径；报告通道（卡片/RPC）与注册行为不受影响

#### Scenario: 反馈内容边界
- **WHEN** 反馈消息被构造
- **THEN** 消息仅含插件标识、状态、路径（成功时）、发现状态与模型数等最小信息，不含报告 JSON 内容、逐模型清单、价格或凭据；路径经过编码安全处理，换行与控制字符被转义

#### Scenario: TUI 双通道并存
- **WHEN** `conversationFeedback` 开启且用户在 TUI 执行导出成功
- **THEN** TUI 卡片照常显示（含打开/复制动作），会话中同时出现对话反馈消息；两条通道内容不冲突

#### Scenario: 反馈提交失败
- **WHEN** 会话输入通道提交反馈失败或长时间未完成（如会话正忙、API 拒绝或挂起）
- **THEN** 报告文件与命令执行结果保持完整，既有卡片/RPC 通道照常更新，命令执行不被无限阻塞，插件不无限重试或抛出未处理错误

#### Scenario: 模型生成失败不丢失反馈
- **WHEN** 反馈消息已成功提交，但其后宿主模型回复生成失败、被取消或无可用模型
- **THEN** 已提交的反馈消息保留在会话中，路径信息不丢失；插件不因此重试或修改会话
