# model-audit-export Specification

## Purpose

允许用户主动从自己的已连接 OpenCode 环境导出插件提交的模型注册结果及其协议选择，以便核对最终映射字段，同时清楚标记发现时点和失效状态，并避免泄露连接凭据或原始上游响应。

## Requirements
### Requirement: 主动触发并获知结果
插件 SHALL 提供用户明确调用的导出命令 `/litellm-audit-export`，执行本地文件写入并向当前 TUI 在该会话区域显示可留存的结果卡片：成功时展示完整绝对路径和可点击的打开、复制动作，失败时显示简短原因；无法打开或复制时 SHALL 显示明确反馈、保留路径且不破坏报告。卡片不是宿主的历史对话消息，SHALL 不要求模型调用或将文件路径提交给模型；重新启动 TUI 可经 `latest` 恢复最近一次导出结果（仍按 sessionID 关联），但不承诺完整的跨进程历史。导出失败不得影响模型注册与发现轮询；无 TUI 客户端 SHALL 可经公开导出 RPC 主动取得结构化结果。插件 MUST NOT 在启动、连接或常规轮询期间无提示地自动写出报告。

#### Scenario: 用户主动导出
- **WHEN** 用户在已连接的 OpenCode 中调用 `/litellm-audit-export`
- **THEN** 插件在用户可定位的本地位置生成审查 JSON，该会话的 TUI 结果卡片显示完整绝对路径、成功状态以及打开文件和复制路径的操作，且不触发新的模型调用

#### Scenario: 已打开的 TUI 即时接收结果
- **WHEN** 用户在已经打开的当前会话执行导出命令，或同一会话的导出 RPC 完成，而完成事件未使卡片重新渲染
- **THEN** TUI 仍在该会话中及时显示新结果及完整路径／失败原因，不要求退出、重进或发送模型消息；不同会话不得显示该结果

#### Scenario: Windows Terminal 中连续导出
- **WHEN** 用户在可见 Windows Terminal 中先打开会话，再实际输入并提交导出命令，随后再次导出
- **THEN** 每次命令离开输入框后，结果卡片无需重启、切换会话或强制刷新即可显示最新完整路径；导出后另开终端恢复已有结果不能替代活跃窗口的验收

#### Scenario: 浅色与深色主题中可见
- **WHEN** 用户使用浅色或深色主题，或在已有卡片显示时切换主题
- **THEN** 标题、完整路径、按钮、失败原因和操作反馈均使用当前宿主主题的可读文字颜色，不依赖 OpenTUI 默认白色；只检查字符存在的测试不能作为视觉可见性证据

#### Scenario: 同会话留存与多会话隔离
- **WHEN** 用户导出后切换会话或重新启动同一服务的 TUI
- **THEN** 卡片只在关联的会话显示；重新启动时可通过 `latest` 恢复最近一次结果，而不会把其他会话的路径展示为当前会话的报告，且卡片不冒充历史对话消息

#### Scenario: 打开或复制失败
- **WHEN** 系统没有可用的文件打开器或剪贴板工具，或相应操作失败
- **THEN** 卡片保留完整路径并显示失败反馈，不自行调用模型、不覆盖或删除报告

#### Scenario: 文件不可写
- **WHEN** 目标目录不可写或磁盘写入失败
- **THEN** 用户收到明确失败信息，已注册模型、现有轮询与 reload 行为保持不变，不留下误标为完整的报告

### Requirement: 内容与注册快照一致
导出 SHALL 覆盖同一活动连接的一次成功发现快照中插件实际提交给 `ProviderEditor.add` 的允许的 provider 字段和全部模型，保持模型数量、ID 和排序一致；每模型 SHALL 包含最终 id、modelID、providerID、显示名、所选协议及 package、工具与输入／输出模态、variant id 与 settings、状态、enabled、发布日期、上下文／输入／输出限制、输入／输出／缓存读／缓存写价格及单位。模型名和推理等级 SHALL 保留实际注册值，不得以“敏感”为由省略或静默改写。报告 SHALL 标明它反映的是“插件传给宿主的值”，而非声称包含宿主后续修改后的完整运行时配置；协议是由同一快照关联的插件选择结果，不得伪称为宿主原生字段。报告 SHALL 定义 schema 版本、已知时间与价格单位，并明确发布日期的原值及单位未知时的含义，以及缺失和默认值的含义。

#### Scenario: 最终映射与协议
- **WHEN** 同次发现注册了 Chat 与 Responses 模型，包含推理档位、价格阶梯截断和上下文限制
- **THEN** 报告的模型集合和排序与该次插件提交的注册输出一致，逐模型协议与 package 对应，variants、价格和限制为实际提交值而不是未转换的 LiteLLM 响应

#### Scenario: 无推理档位或未知字段
- **WHEN** 模型未获得可用的推理档位或某字段只取得默认值
- **THEN** 报告使用约定的空数组／默认值和说明，不将未知情况虚构为经上游验证的事实

#### Scenario: 发布日期保留注册原值
- **WHEN** 某模型的发布日期由日期字符串解析而来，另一模型的上游发布日期直接给出数值
- **THEN** 报告对两者均保留提交给宿主的数值；明确前者当前为 Unix 毫秒，后者未经单位归一化、单位未知，不将两者一律标成秒

### Requirement: 标记发现状态与连接边界
导出 SHALL 显示导出时间、最近一次成功发现时间及当前发现状态，并区分未连接、尚无成功发现、正常结果、临时故障保留旧结果、认证失败撤下结果、连接切换待发现、以及成功发现空清单。切换或断开连接后 MUST NOT 导出前一连接的模型为当前可用模型；发现失败期间 MUST NOT 将保留的旧结果标记为刚刚成功发现。

#### Scenario: 短暂网络故障
- **WHEN** 最近一次成功发现后出现网络故障，插件保留先前注册的模型
- **THEN** 导出可以列出保留结果，但明确标记为旧结果并记录最近一次成功发现时间，而非声称当前已完成发现

#### Scenario: 连接切换和认证失败
- **WHEN** 用户切换活动连接后尚未成功发现，或新连接返回 401／403
- **THEN** 报告不包含前一连接的模型，并分别标记待发现或认证失败且已清空

#### Scenario: 空清单与未连接
- **WHEN** 成功发现但对话模型数为零，或当前没有活动连接
- **THEN** 报告分别标明成功且为空、未连接，不以同一个空数组掩盖两种状态

### Requirement: 最小化数据与安全写入
导出 SHALL 仅以显式字段 allowlist 构造报告，MUST NOT 将 API Key、Authorization、凭据对象／ID、原始 `/v1/model/info` 或 models.dev 响应、prompt／请求体、私有 `api_base`、上游路由、完整 LiteLLM 地址或其他未经筛选的可扩展设置作为额外字段输出；默认文件位置、访问权限与覆盖策略 SHALL 在使用说明中明确，写入失败 MUST NOT 破坏已有完整文件。模型名、variant id 与允许的 settings 值本身是审查对象，SHALL 原样导出；插件不承诺识别或过滤这些允许字段值中的任意内部信息。文档 SHALL 提醒用户模型名与价格可能属于内部信息，分享前需审查报告。

#### Scenario: 非导出字段中的敏感数据
- **WHEN** 连接凭据、源响应中未用于最终注册的字段、或未获允许的可扩展设置含有测试 Key、私有地址、路由和其他敏感标记，且正常模型名和推理等级可供导出
- **THEN** 报告与命令反馈不从这些非导出字段复制敏感标记，同时报告保留模型名、推理等级等允许字段的真实注册值

#### Scenario: 允许字段中的信息
- **WHEN** LiteLLM 模型名或推理等级包含用户认为需要保密的内部命名
- **THEN** 主动生成的报告仍与注册输出一致地保留这些值，用户在分享文件前可按文档提示自行审查

#### Scenario: 多次导出
- **WHEN** 用户连续两次主动导出，第二次写入失败
- **THEN** 第一次的完整文件仍可读取，不会被损坏或部分覆盖
