## Context

四条 PR 的工具链已把启动准备、roots 发现与排队锁放进同一 stdio wrapper，但异步生命周期仍有三处缺口：门禁结论没有轮次归属，关闭状态没有取消语义，协议进程仍可能同步解析项目身份。回归侧则存在"barrier 位置在调用之外"和"历史回放切掉辅助函数"两个证据强度问题。

## Goals / Non-Goals

- Goals：三处 P2 缺陷修复；排队与历史回放的负向控制真实有效；四仓库共享实现与共享回归逐字节同构。
- Non-Goals：不改变产品 API、宿主适配层、dist/provenance、模型发现与注册；不合并 PR、不打 tag、不变更仓库策略。

## Decisions

- **轮次隔离而非"等待后合并"**：显式准备与后台准备可能并发且没有全局先后关系，等待无法区分谁更新。改为每根递增轮次，回调携带轮次，只有最新轮次可写结论；显式准备在写入前也占用新轮次，因此旧后台回调天然失效。
- **关闭状态而非仅 kill 当前集合**：泄漏来自创建完成晚于 cleanup 的会话。统一跟踪创建中 Promise 与已建立会话，创建完成时若已关闭则立即释放；准备子进程同样登记并在关闭时取消。
- **扫描移出协议进程而非缩小子进程超时**：慢解析本身合法（大工作区、慢磁盘、原生 CLI 冷启动），缩时会把正确工作误判为失败。工作区扫描和 roots 归一化只在子进程执行并回传 JSON，协议进程只保留非阻塞的异步 Git 调用；扫描期间用门禁 pending 挡住查询，保持"等待而不是穿透"。
- **回归卡住实现自身的锁前读取**：barrier 由 fixture 的 `services.repository` 第一次调用触发，旧实现的锁前快照因此确实带着旧 HEAD 进入锁内；只把排队用例的负向控制指向真正携带该快照的提交（`7e9b0e1`），审核前基线继续覆盖其余旧故障。
- **历史回放只替换 `api()`**：按括号配对替换签名与函数体，避免删掉 `remaining()` 等旧状态机仍调用的辅助函数；转发参数按该版本实际声明的名字选择，保持各版本自身语义。

## Risks / Trade-offs

- 子进程往返比进程内调用多一次 spawn（每次准备一次，约毫秒级），换取协议进程零同步阻塞。
- `CBM-PREPARE-ROUNDS` 依赖 GitHub CLI 的真实超时路径，缺少 `gh` 时跳过并显式说明；其余回归不依赖网络。
- 关闭状态下显式准备返回失败而不是静默成功，调用方看到的是连接已关闭的错误。

## Migration

无需迁移。四仓库共享脚本与共享测试同步更新；workspace 的客户端与客户端测试保持 workspace 专属。文档更新 `docs/codebase-memory.md`、`docs/decisions.md` 与 `docs/main-index-sync-review.md`。
