# v0.10.1 — 模型能力元数据匹配修正

v0.10.1 修正 LiteLLM 已发现模型与 models.dev 能力记录的匹配方式，让 OpenCode 注册模型时使用与模型身份对应的能力和推理选项。

## 用户可见变化

- LiteLLM 继续提供当前 API Key 可用的部署列表；Core 根据模型名称和可信 canonical 身份关系选择 models.dev 记录，来源优先级为官方服务商、OpenCode、OpenRouter。自动配置不再要求证明实际请求会发往哪个服务商，也不要求设置 `models_dev_provider`。
- 推理支持与可选档位分别处理。OpenCode 只暴露所选记录明确声明的 `reasoning_options`，不生成未声明的 variants。
- 价格是可选参考值。价格缺失或无效按零处理，不影响模型能力、注册可用性或缓存恢复。

## 升级

无需更改 LiteLLM endpoint、凭据或模型配置。此前为自动元数据匹配而设置的 `models_dev_provider` 不再是必要条件。
