# v0.3.0 — discovery quality、诊断与跨仓库稳定性

v0.3.0 汇总 v0.2.0 之后已经合入并验证的 Discovery Core 演进。插件继续通过 LiteLLM `/v1/model/info` 自动发现模型，并在构建期固定共享 Core SHA；本版重点提升刷新/缓存、持久化快照、诊断、模型能力识别和 models.dev 元数据补缺的可靠性。

## 主要变化

- 引入共享 refresh coordinator：singleflight、短时缓存、退避与 last-known-good 降级。
- 增加 endpoint-bound discovery snapshot 与恢复/漂移判断。
- 新增 `/litellm-diagnostics`，展示发现、缓存、models.dev、协议和 Core provenance；诊断绝对时间按运行 OpenCode 的宿主时区显示。
- TUI diagnostics / audit 结果卡片支持 `[关闭]`，同一 sequence 不会被 latest 轮询重新弹回。
- 提升 discovery quality：context / input / output 上限分离、reasoning/protocol capability 来源可诊断、unknown/private 模型保持可发现。
- models.dev 能力补缺改为“原厂（优先 canonical identity）→ OpenRouter → OpenCode → 全局唯一记录”；解决类似 `hy4-preview` 因多 provider 歧义导致 context/output 变成 0 的问题。
- 明确 LiteLLM 显式价格优先；models.dev fallback 主要用于能力、限制、模态和 reasoning 元数据。
- 跨仓库 Core compatibility、分发 provenance、OpenSpec Scenario 测试和 archive 闭环均已强化。

## 版本溯源

- 本版插件构建固定共享 Core：`rpchen/litellm-discovery-core` / `main` / `e5f6393c12fc199bd8466e9d01dd5914ad6b74d8`。
- 实际 Core SHA 仍以 tag 中的 `dist/core-provenance.json` 为准。
- Release workflow 会重新执行 committed-dist、delivery integrity、typecheck、unit tests、TUI、clean distribution、OpenSpec、tarball 安装和 tagged Git 安装。

## 安装与升级

跟随最新稳定分支：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider
```

固定安装 v0.3.0：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider#v0.3.0
```

已有跟随 main 的安装可执行：

```sh
opencode reload
opencode plugin update "github:rpchen/opencode-litellm-provider"
opencode reload
opencode plugin list
```

## 发行附件

Release workflow 会生成 `opencode-litellm-provider-0.3.0.tgz` 及对应 SHA-256 校验文件，并在上传后重新下载验证归档字节和解包后的 `dist`。
