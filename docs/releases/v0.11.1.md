# v0.11.1 — 暂停模型过滤修复

v0.11.1 修复 LiteLLM 管理员暂停模型后，OpenCode 仍显示这些模型的问题。

## 用户可见变化

- 修复重新启用已缓存 endpoint 后模型不发布、状态回退，以及不同目录会话中的启用位置问题；重叠的启停请求按顺序保留所有更新。
- LiteLLM Models 页面 Disable 操作产生的 `model_info.blocked: true` deployment 不再参与模型发布；同名模型全部暂停时，在下一次成功刷新后撤销已有注册。
- 同名模型仍有可用的对话 deployment 时继续参与发现；embedding 等非对话模型不进入模型选择器。
- 暂停状态变化通过共享 Core 的归一化模型集合参与增量刷新，避免旧 publication/LKG 恢复已暂停模型；另一 endpoint 的模型集合保持独立。
- 继续使用 `/v1/model/info`（旧版回退 `/model/info`），无需增加 `/v1/models` 请求或修改用户配置。

## 升级

固定安装版本使用 `opencode plugin add github:rpchen/opencode-litellm-provider#v0.11.1`。

## 构建与验证

内嵌 discovery Core 固定为 `1ff0979c8f22ec06479331d94ced2cf466f1fd42`。产品修复已通过真实 OpenCode 2.0.16 / 2.0.30 宿主验收。测试以本地模拟 LiteLLM 和合成数据验证运行中模型20→13、诊断同步与 endpoint 隔离；这些数量不代表公司服务线上实测。
