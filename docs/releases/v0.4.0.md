# v0.4.0 — multi-endpoint activation

v0.4.0 introduces global multi-endpoint support while preserving the historical single-endpoint experience with zero migration.

## 主要变化

- 支持在全局插件配置中定义多个 LiteLLM endpoint；PR9 不引入项目级 endpoint。
- `default` 继续沿用历史 `litellm` integration/provider identity；其他 endpoint 使用 `litellm-<id>`。
- endpoint id 使用共享 Core 契约 `[a-z0-9][a-z0-9-_]*`。
- 每个 endpoint 拥有独立凭据、发现循环、缓存/snapshot、provider 状态和故障域。
- 新增 `/litellm-endpoints` activation 管理，可启用全部、任意子集或零个 endpoint；停用不会删除定义、凭据或 snapshot。
- diagnostics 与 audit 变为 endpoint-aware；audit 只汇总当前激活 endpoint。
- 显式 endpoint identity 进入 discovery snapshot fingerprint；legacy 单 endpoint 继续省略 identity，因此旧 fingerprint 和恢复行为保持兼容。
- committed dist 固定到共享 Core `8e155e0efe90f1e9e7c8e973239c206a97011477`。
- 新增跨 endpoint snapshot 隔离、activation、TUI 生命周期和 installed-package 命令/清理契约测试。

## 范围边界

本版本不包含 endpoint 完整 CRUD UI、项目级 endpoint、跨 endpoint 聚合、负载均衡或自动故障切换。endpoint 定义仍由全局配置维护。

## 安装与升级

跟随最新稳定分支：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider
```

固定安装 v0.4.0：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider#v0.4.0
```

已有跟随 main 的安装：

```sh
opencode reload
opencode plugin update "github:rpchen/opencode-litellm-provider"
opencode reload
opencode plugin list
```

升级后，未配置 `endpoints` 的用户继续按原来的单 endpoint 配置工作，无需迁移。

## 验证

Release workflow 会从 tag 固定的 Core provenance 重新执行 committed-dist、delivery integrity、typecheck、全量单测、TUI render/mouse、clean distribution、OpenSpec、tarball 安装、tagged Git 安装，并在发布后重新下载附件核验 SHA-256 与解包后的 dist。
