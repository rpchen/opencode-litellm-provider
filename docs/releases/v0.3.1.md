# v0.3.1 — operational model guard 与治理收口

v0.3.1 是 v0.3.0 之后的稳定性修复版，重点把本轮真实宿主测试暴露出的规则从“具体模型回归”提升为通用发布边界。

## 主要变化

- OpenCode 不再发布 `context <= 0` 或 `output <= 0` 的不可用模型定义；Core diagnostics 仍可保留这些模型用于解释。
- Pi 同样使用共享 Core 的 `hasOperationalLimits()` 不变量，避免生成 `contextWindow: 0 / maxTokens: 0`。
- models.dev 能力匹配继续采用 canonical 原厂 → OpenRouter → OpenCode → 全局唯一记录的优先级。
- provider fallback 仅用于能力补缺时，不会把 reseller 价格冒充为当前 LiteLLM 路由价格。
- 两端 committed dist 已更新到共享 Core `f2bb196350c6f8db406bfaff3321c2358fa04ed4`。
- README、OpenSpec、跨仓库测试、发布治理与会话 retrospective 规则同步收口。

## 安装与升级

跟随最新稳定分支：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider
```

固定安装 v0.3.1：

```sh
opencode plugin add github:rpchen/opencode-litellm-provider#v0.3.1
```

已有跟随 main 的安装：

```sh
opencode reload
opencode plugin update "github:rpchen/opencode-litellm-provider"
opencode reload
opencode plugin list
```

## 验证

Release workflow 会从 tag 固定的 Core provenance 重新执行 committed-dist、delivery integrity、typecheck、单测、TUI、clean distribution、OpenSpec、tarball 安装与 tagged Git 安装，并在发布后重新下载附件核验 SHA-256 与解包后的 dist。
