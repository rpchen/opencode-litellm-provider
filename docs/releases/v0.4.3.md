# v0.4.3 — Multi-endpoint TUI and diagnostics reliability fixes

v0.4.3 is a patch release for the user-visible issues found after v0.4.2 while validating explicit multi-endpoint workflows in real OpenCode 2.0.16 sessions.

## Fixed

- `/litellm-endpoints` now uses OpenCode's native selector instead of a pseudo-interactive text card.
  - keyboard navigation works with ↑ / ↓ and Enter,
  - Esc closes the selector,
  - mouse/focus behavior is delegated to the host-native control.
- LiteLLM commands issued during TUI startup no longer appear to do nothing when their one-shot RPC event is emitted before the terminal listener is ready.
  - endpoint-selector show requests are recoverable from endpoint state,
  - diagnostics results are recoverable from the latest-result channel.
- `/litellm-diagnostics <endpoint-id>` now actually scopes to the requested endpoint.
  - OpenCode V2 carries the slash-command tail in the command invocation's `prompt.text`,
  - the plugin now reads and trims that canonical field,
  - unknown endpoint ids are reported explicitly instead of silently falling back to the overview.
- README examples now document endpoint-scoped diagnostics such as:
  - `/litellm-diagnostics company`
  - `/litellm-diagnostics cd-vpn`

## Real OpenCode 2.0.16 E2E coverage

The permanent real-host gate now reproduces the workflows that exposed these bugs:

1. install the exact candidate Git commit through OpenCode's own plugin installer,
2. start a real OpenCode 2.0.16 server and terminal client,
3. execute LiteLLM commands before endpoint credentials exist and verify startup recovery,
4. configure two independent fake LiteLLM endpoints and credentials,
5. open the real `/litellm-endpoints` selector and toggle an endpoint with keyboard input,
6. verify the disabled provider/model namespace disappears while the other remains available,
7. re-enable the endpoint through the same selector and verify discovery resumes,
8. execute endpoint-scoped diagnostics through the real session command API with `text: "company"`,
9. require the terminal to show the company endpoint's detailed diagnostics,
10. negatively assert that scoped diagnostics do not fall back to the multi-endpoint overview.

The E2E uses isolated HOME/XDG directories and local fake LiteLLM servers only; it does not read user configuration or real credentials.

## Release metadata cleanup

This release also repairs two historical package-lock metadata fields that were accidentally changed by earlier release-version replacement:

- `bun-ffi-structs` is restored to `0.3.1`,
- `json-schema` is restored to `0.4.0`.

Their resolved tarballs already pointed to those versions; this change restores the lockfile metadata without changing the dependency graph.

## Install / upgrade

Follow the latest stable main:

```sh
opencode plugin update "github:rpchen/opencode-litellm-provider"
```

Or pin v0.4.3:

```sh
opencode plugin add github:rpchen/opencode-litellm-provider#v0.4.3
```

After upgrading from v0.4.2, fully restart OpenCode so both the server plugin and terminal TUI load the same candidate.

## Verification

Before tagging, the release candidate must pass the normal delivery CI and the dedicated **Real OpenCode 2.0.16 E2E** job on `main`.

The tag-triggered Release workflow then re-verifies:

- release version / manifest / lockfile consistency,
- OpenSpec closure,
- committed distribution at its fixed Core provenance,
- delivery integrity,
- typecheck and all unit tests,
- TUI render checks,
- clean distribution rebuild,
- package installation from both tarball and Git tag,
- generated release tarball and SHA-256 checksum,
- downloaded published assets and extracted `dist` byte-for-byte equivalence.

Committed discovery Core remains pinned to `8e155e0efe90f1e9e7c8e973239c206a97011477`.
