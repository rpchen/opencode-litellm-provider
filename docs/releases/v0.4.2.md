# v0.4.2 — Real OpenCode 2.0.16 integration-schema fix

v0.4.2 fixes the multi-endpoint regression found by real OpenCode 2.0.16 usage after v0.4.1.

## Fixed

- `/plugins` no longer causes the built-in `opencode.config.provider` plugin to fail with `Integration.Info` schema validation.
- `/connect` can again see independent LiteLLM integrations such as **LiteLLM** and **LiteLLM · company**.
- `/models` / `opencode models` again expose models under both `litellm/*` and `litellm-<endpoint>/*`.
- Fixed-baseUrl endpoint authentication no longer emits illegal `form: []`. OpenCode 2.0.16 defines the optional auth form as a non-empty field array; when no extra field is needed, the plugin now omits `form` entirely.
- Integration editor typing is now derived from OpenCode's `Plugin.Context` instead of a looser hand-maintained shadow interface.

## Permanent real-host gate

CI now includes a dedicated **Real OpenCode 2.0.16 E2E** job. It:

1. installs the exact `@opencode/cli@2.0.16` host,
2. installs the current plugin through OpenCode's own `plugin add github:<repo>#<full-sha>` path,
3. starts one isolated real OpenCode server,
4. configures two fake LiteLLM endpoints with two different fake API keys,
5. verifies the real integration registry contains `litellm` and `litellm-company`,
6. stores independent credentials through the real integration API,
7. proves each fake LiteLLM receives its own authenticated discovery request,
8. verifies both providers become available,
9. runs real `opencode models` and requires both provider namespaces,
10. verifies `litellm-endpoints`, `litellm-diagnostics`, and `litellm-audit-export` are registered.

The E2E uses an isolated HOME/XDG environment and local fake LiteLLM servers only; it does not read user configuration or real credentials.

## Multi-endpoint API keys

For:

```jsonc
{
  "endpoints": {
    "default": { "baseUrl": "https://personal.example" },
    "company": { "baseUrl": "https://company.example" }
  }
}
```

run `/connect` separately for:

- **LiteLLM** → `litellm`
- **LiteLLM · company** → `litellm-company`

Each integration stores and resolves its own API Key. Because the endpoint URL is already fixed in plugin options, `/connect` asks only for the API Key.

## Install / upgrade

Follow the latest stable main:

```sh
opencode plugin update "github:rpchen/opencode-litellm-provider"
```

Or pin v0.4.2:

```sh
opencode plugin add github:rpchen/opencode-litellm-provider#v0.4.2
```

After upgrading from v0.4.1, fully restart OpenCode so the server process loads the new committed distribution.
