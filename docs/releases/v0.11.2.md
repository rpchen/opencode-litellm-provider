# v0.11.2 — 冷启动快照恢复修复

v0.11.2 修复重启后首次模型列表无法立即使用本地成功快照的问题，并兼容 OpenCode 新版凭据中的地址字段。

## 用户可见变化

- 启动时先发布与当前 endpoint、配置和凭据兼容的成功快照，不等待网络发现；单 endpoint 与多 endpoint 行为一致。
- 快照模型显示为“来自上次快照、待确认”。暂时网络失败时继续保留，后台发现成功后更新；认证失败或 model/info 不可用仍按原规则撤下模型。
- 在同一连接中更换 API Key 后，旧快照及其状态同步失效。若新发现失败，显示实际错误，不再误报正在使用旧快照。
- 兼容 OpenCode 凭据的 `metadata.url`，保留旧版 `configuration.url` 支持；宿主兼容范围扩展为 `>=2.0.15 <2.3`。

## 升级

```bash
opencode plugin add github:rpchen/opencode-litellm-provider#v0.11.2
```

无需修改现有 endpoint 配置。没有兼容快照时，模型仍需等待首次成功发现。

内嵌 discovery Core 保持为 `1ff0979c8f22ec06479331d94ced2cf466f1fd42`。产品变更及凭据轮换回归已通过 244 项插件测试和真实 OpenCode E2E；真实宿主测试使用本地模拟 LiteLLM，不代表生产服务实测。CI 每次解析最新稳定宿主的精确版本进行验证。发布流程另对 tag 对应产物执行固定 provenance 复验和附件回读校验。
