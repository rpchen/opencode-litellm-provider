# v0.9.0 — 只有可信配置才会提供给 OpenCode

v0.9.0 是一个 minor 版本：插件现在把"模型存在"和"模型配置可被信任"明确分开。metadata 来源临时故障、来源之间出现差异、模型信息发生变化时，OpenCode 会尽最大努力保持可用，同时绝不降低单个模型的配置质量门禁。

## Highlights

- **不可信配置不再进入 `/models`**：只有完整、可信的模型配置才会注册；不完整的模型保持 withheld，并在 diagnostics 中说明原因。
- **一个模型失败不影响其他模型**：同一 endpoint 上可信的模型照常发布，不需要你先确认任何内容。
- **metadata 临时不可用时保护已验证配置**：此前完整通过验证的模型继续可用（trusted LKG），并标注来源与年龄。
- **权威裁决而不是机械冲突**：LiteLLM 描述性 metadata 与 models.dev 的模型内禀事实不一致时，采用更权威的来源并记录这次差异，不再因此把模型判为不可用。
- **withheld 模型自动恢复**：不需要任何"接受降级"的动作；模型重新达到标准后自动回到 `/models`。
- **删除 `/litellm-accept-degraded`** 与 publication RPC 的 `accept` 方法：任何客户端动作都无法影响发布结果。

## 为什么模型可能暂时不可用

endpoint 里发现了模型，不等于它已经可以被安全使用。只有能力信息完整可信（上下文窗口、输出上限、工具调用、reasoning、输入/输出模态等足以让 OpenCode 正确调用）的模型才会进入 `/models`，其余模型保持 withheld，并在 `/litellm-diagnostics` 中连同原因列出：metadata 来源暂时不可用、metadata 不完整、身份无法可靠确定、权威冲突无法裁决、metadata 非法。

```text
发现 20 个模型
→ 17 个立即正常进入 /models
→ 3 个 withheld（在 diagnostics 中说明原因）
```

这叫 **partial availability**，是正常可用状态，不需要你确认任何内容。

## metadata 临时故障时保护已验证配置

如果某个模型此前完整通过过可信发布标准，且它的身份（provider / canonical 身份）没有变化、也没有出现新的高权威矛盾事实，插件会继续使用这份**此前验证过的完整配置**，并在 diagnostics 中标注"使用已信任的前次完整配置（LKG）"及其来源时间与年龄。

LKG 不是猜测，也不是降级模型：它就是一份曾经整体成立的可信配置。它没有固定过期时间——是否继续使用由身份、provider、schema 与 live 事实是否一致决定。LiteLLM 已经不再提供的模型不会因为存在 LKG 而重新出现。

## 描述性 metadata 与权威事实

LiteLLM `/v1/model/info` 的 `model_info` 是描述性注册信息，不是 endpoint 强制执行的运行约束。当它与可信的 models.dev 内禀事实不一致时：

- 模型内禀事实（上下文/输出上限、模态、工具、reasoning）采用更权威的来源，差异作为**已裁决差异**记录在 diagnostics 中；
- 只有运维者自己的部署配置（`litellm_params`）中可证明被 endpoint 执行的限制才会收窄最终配置；
- 只有真正无法裁决的冲突才让模型 withheld（显示为"未决冲突"）。

## 撤回、恢复与终止状态

如果你之前用过的模型**现在**被 withheld，这是一次 regression：诊断会明确写出"此前可用、现已撤下"以及原因；插件不会自动切换你的模型，也不会静默继续使用失去可信配置的模型。

被 withheld 的模型继续参与正常发现与刷新，一旦重新达到可信标准就自动回到 `/models`，无需你再次批准。整个 endpoint 当前没有任何模型可安全发布时，诊断会直接说明"endpoint 连接成功，但本轮没有任何模型达到可信发布标准"，而不是看起来像插件没有反应。

同一组已确认的问题不会在 OpenCode 重启后反复打扰你；出现新的问题、或原本正常的模型被撤下时会再次提醒。

## metadata 来源可覆盖

新增 `modelsDevUrl` 选项：可以把 catalog 指向自托管或镜像地址（默认 `https://models.dev/api.json`）。抓取到的元数据仍走同一套证据与发布规则。

## Compatibility

- **无需迁移**：endpoint 配置、凭据、激活状态与缓存格式不变；
- `/litellm-accept-degraded` 与 publication RPC `accept` 已删除；此前需要它们的模型现在只有两种结局——重新达到可信标准后自动发布，或保持 withheld 并在 diagnostics 中说明原因；
- 新版本会更保守地发布模型：这是预期行为，避免把不可信配置交给 OpenCode。

## 安装 / 升级

跟随最新稳定 main：

```bash
opencode plugin add github:rpchen/opencode-litellm-provider
```

或锁定 v0.9.0：

```bash
opencode plugin add github:rpchen/opencode-litellm-provider#v0.9.0
```

从 v0.8.0 升级后重启 OpenCode 即可；无需迁移配置。
